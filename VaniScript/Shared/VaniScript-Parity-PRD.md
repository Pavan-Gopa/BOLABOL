# PRD: Приведение VaniScript (Electron) и VaniScript (Apple Silicon) к единому виду

**Дата:** 2026-07-01
**Автор аудита:** анализ кодовых баз
**Статус:** черновик для передачи разработчику
**Задача:** зафиксировать все функциональные расхождения между двумя версиями и описать, где и что менять. Реализация — отдельным этапом.

---

## 0. Объекты сравнения

| | Electron-версия | Apple Silicon (нативная) |
|---|---|---|
| Папка | `VaniScript/` | `VaniScriptAppleSilicon/` |
| Стек | React 19 + TypeScript + Vite + Electron | SwiftUI + Swift, `VaniScript` (UI) + `VaniScriptCore` (логика) |
| Главный файл UI | `src/App.tsx` (3233 строки) | `Sources/VaniScript/Stores/WorkflowStore.swift` (~2600 строк) + `Views/*` |
| Транскрипция (локально) | whisper.cpp / llama.cpp (`localAsrModels`) | WhisperKit / Core ML |
| LLM (локально) | llama.cpp (`localTranslationModels`) | MLX Swift |
| Облако | Gemini Cloud, GPT Cloud | Gemini Cloud, GPT Cloud |

**Важно про локальные движки.** Различие whisper.cpp/llama.cpp ↔ Core ML/MLX — это осознанное архитектурное решение (нативная версия и делалась ради Apple Silicon). Приводить эти движки «к единому виду» не нужно. Паритет требуется на уровне **пользовательских функций и UX**, а не бэкенда инференса. `[высокая]`

**Терминология.** «Сегмент» (native) и «чанк» (Electron) — это одно и то же: кусок аудио/видео, который транскрибируется и ревьюится отдельно. Далее использую «сегмент».

## 2. Пункт 1 — Онбординг при первой установке

### 2.1 Текущее состояние

**Electron — онбординг включён по умолчанию.** `[высокая]`
- Рендер тура: `src/App.tsx:3217` — `{settings.annotationMode && (<OnboardingTour .../>)}`.
- Значение по умолчанию: `src/services/storage.ts:19` — `annotationMode: true`; при загрузке `:122` — `annotationMode: parsed.annotationMode !== false` (то есть по умолчанию включён, пока пользователь явно не выключит).
- Компонент: `src/components/OnboardingTour.tsx` (805 строк). Тур сквозной, привязан к элементам через атрибуты `data-tour="..."` (settings-btn, workspace-dropzone, target-lang-select, transcription-model-select, review-pane-original, approve-next-btn, export-documents, shorts-panel и т.д.) и ведёт пользователя через все экраны по мере работы.
- Переключатель: иконка `HelpCircle` в тулбаре ревью (`src/App.tsx:2447–2457`) включает/выключает `annotationMode`.

**Apple Silicon — инфраструктура тура есть, автозапуска нет.** `[высокая]`
- Экран тура: `Views/OnboardingTourView.swift` (18 КБ), шаги в `TourSteps`, подсветка целей через модификатор `.onboardingTarget("...")` (например `Views/UploadWorkspaceView.swift:24,36,46`, `Views/ContentView.swift:53`).
- Состояние в сторе: `Stores/WorkflowStore.swift:12–17` (`isTourActive`, `tourStepIndex`, `tourLanguage`, `activeTourScreen`), методы `startTour/nextTourStep/prevTourStep/skipTour` (`:100–141`).
- Язык тура определяется по локали системы (`:88–93`): `ru`/`en`.
- **Запуск только вручную:** кнопка «?» (`questionmark.circle`) в `Views/ContentView.swift:27–33` вызывает `startTour(...)`. Автоматического показа при первом запуске нет, флага «онбординг пройден/показан» в `AppSettings`/`UserDefaults` нет.

### 2.2 Целевое поведение

При первом запуске нативного приложения (свежая установка, тур ещё не показывался) онбординг-тур должен запускаться автоматически, как в Electron. Повторно при последующих запусках — не показывать. Кнопка «?» остаётся для ручного повторного запуска.

### 2.3 Что менять (Apple Silicon)

1. Добавить persist-флаг первого запуска — поле в `AppSettings.swift` (например `hasCompletedOnboarding: Bool = false`) либо ключ `UserDefaults`. `[высокая]`
2. Автозапуск при старте: в `Views/VaniScriptApp.swift` или в `ContentView.body`/`onAppear` — если флаг `false` и это первый экран (`upload`), вызвать `workflowStore.startTour(for: "upload")` и по завершении/скипу выставить флаг в `true` (в `nextTourStep` при последнем шаге и в `skipTour`, `WorkflowStore.swift:126,139`). `[высокая]`
3. (Опционально, для полного паритета UX) сделать тур сквозным между экранами, как в Electron, а не только «по кнопке для текущего экрана». Сейчас `startTour(for:)` завязан на текущий экран; для сквозного прохождения нужно продолжать тур при смене `workflow.screen`. `[средняя]`

### 2.4 Критерии приёмки
- Чистая установка → при первом открытии сразу показывается тур.
- Прохождение до конца или «Skip» → флаг сохраняется, при следующем запуске тур не появляется.
- Кнопка «?» по-прежнему запускает тур вручную.

## 3. Пункт 2 — Информация об исходном видео и качество (сайдбар + Info)

### 3.1 Текущее состояние

**Apple Silicon — полноценная функция.** `[высокая]`
- Модель данных: `VaniScriptCore/MediaSource.swift`, структура `SourceMediaInfo` (`:40–60`) с полями: `fileName`, `title`, `kind`, `durationSec`, `fileSizeBytes`, `width`, `height`, `frameRate`, `videoCodec`, `audioCodec`, `container`, `writingApplication`, `overallBitrateBps`, `videoBitrateBps`, `audioBitrateBps`, `audioSampleRateHz`, `audioChannelCount`, `importedAt`, `originalURL`.
- Вычисляемые ярлыки: `qualityLabel` (например «1080p HD», `:108`), `resolutionLabel` (`:121`), сводка `mediaSummary`.
- Извлечение метаданных: `SourceMediaInspector.inspect(...)` (AVFoundation), вызывается при импорте (`WorkflowStore.swift:312,355,410`) и при повторном открытии Info (`:2255`).
- UI в сайдбаре проектов: `Views/ProjectSidebarView.swift` — карточка `sourceMediaCard` (`:214`) c иконкой film/waveform, именем файла, сводкой качества (`:224`), путём (`:232`) и кнопкой **«Info»** (`:240–243`).
- Полное окно: `WorkflowStore.showProjectSourceInfo(id:)` (`:2243`) обновляет метаданные инспектором и показывает `presentSourceMediaInfo` — `NSAlert` «Source Media» (`:2270`) с текстом `sourceInfoDetails` (`:2499`) и кнопками «Open File» / «Reveal in Finder» / «OK».

**Electron — функции нет.** `[высокая]`
- `src/lib/media-source.ts` умеет только классифицировать audio/video/unknown по расширению (`sourceMediaKind`). Никакого зондирования разрешения/кодеков/битрейта нет.
- Упоминания `resolution`/`quality`/`codec` в компонентах (`ShortsReelsPanel.tsx`, `Workspace.tsx`) относятся к пресетам экспорта Shorts и к MediaRecorder, а не к анализу исходника.
- В сайдбаре проектов нет карточки качества и кнопки Info.

### 3.2 Целевое поведение (Electron)

В сайдбаре/списке проектов у каждого источника показывать краткую сводку качества (ярлык качества, разрешение, fps), а по кнопке «Info» открывать окно с полной информацией об исходном файле (контейнер, видео/аудио кодеки, разрешение, fps, битрейты, частота дискретизации, число каналов, размер файла, длительность, путь, оригинальный URL) и действиями «Открыть файл» / «Показать в Finder».

### 3.3 Что менять (Electron)

1. **Извлечение метаданных.** Добавить зондирование через `ffprobe` (в проекте уже есть `ffmpeg-static`; см. `package.json` build → `asarUnpack: node_modules/ffmpeg-static`). Реализовать в main-процессе (`electron/`) IPC-хендлер `media:probe(path)` → JSON с полями, аналогичными `SourceMediaInfo`. `[высокая]`
2. **Модель данных.** Расширить `src/types.ts` типом `SourceMediaInfo` (порт полей из native) и сохранять его в проект/сессию (`session.sourceMediaInfo`), заполняя при импорте файла (`handleFileSelected`, `App.tsx:925`). `[высокая]`
3. **UI-карточка.** В компоненте сайдбара проектов добавить карточку качества (иконка, имя, `qualityLabel`, `resolutionLabel`, fps) + кнопку «Info». Логику ярлыков (`qualityLabel`, `resolutionLabel`) портировать из `MediaSource.swift:108–126`. `[высокая]`
4. **Окно Info.** Модалка с полной сводкой + кнопки «Открыть файл» (`shell.openPath`) и «Показать в Finder» (`shell.showItemInFolder`) через IPC. `[высокая]`
5. **Онбординг/тур:** добавить `data-tour` для новой карточки, если тур должен её упоминать (не обязательно). `[низкая]`

### 3.4 Критерии приёмки
- После импорта видео в сайдбаре видна сводка качества (например «1080p HD · 1920×1080 · 30 fps»).
- Кнопка Info открывает окно с полными техническими данными и рабочими действиями Open/Reveal.
- Для аудио-источников показываются аудио-поля (кодек, битрейт, частота, каналы) без видео-полей.

## 4. Пункт 3 — Ре-транскрибация страницы целиком («Try Transcription»)

### 4.1 Текущее состояние

**Apple Silicon — есть, но частично и условно.** `[высокая]`
- Кнопка «Regenerate Timings» в `Views/ReviewWorkspaceView.swift:350–361` вызывает `store.regenerateCurrentSegment()` (`WorkflowStore.swift:1299`).
- Показывается **только условно** — `shouldShowRegenerateTimings` (`ReviewWorkspaceView.swift:457–462`) возвращает `true`, лишь когда у реплик нет пословных таймингов. Семантически это «пересобрать тайминги», а не «мне не нравится текст — транскрибируй заново».
- Отдельной всегда-доступной кнопки «переснять транскрипцию текущей страницы» нет.

**Electron — рабочей функции нет.** `[высокая]`
- В живом UI ревью (`src/App.tsx`, тулбар `:2429–2467`) кнопки ре-транскрибации нет вообще.
- В `src/components/ChunkReview.tsx:115–117` есть кнопка «Re-transcribe», но **у неё нет `onClick`** и сам компонент **не импортируется** в `App.tsx` (мёртвый код; живой ревью построен на `TextPanel`). Кнопка «Retry» в состоянии ошибки (`:141`) тоже без обработчика.

### 4.2 Целевое поведение (обе версии)

В экране ревью для **текущего сегмента/страницы** должна быть всегда доступная кнопка «Try Transcription» (Ре-транскрибация), которая заново прогоняет транскрипцию этого сегмента текущим выбранным транскрайбером (облако или локальный движок), заменяет `original`/реплики и сбрасывает статус одобрения сегмента. Пользователь применяет её, если результат не устроил.

### 4.3 Что менять

**Apple Silicon** `[высокая]`
1. Добавить в `WorkflowStore` метод `retranscribeCurrentSegment()` — прогон текущего сегмента через транскрипционный пайплайн (`NativeProcessingPipeline`), с учётом выбранного `transcriptionProvider` (облако/Core ML). За основу — существующий `regenerateCurrentSegment` (`:1299`), но без условия «только когда нет таймингов».
2. Добавить в `ReviewWorkspaceView` кнопку «Try Transcription» в `actionBar` (рядом с `:350`), показываемую всегда (не по `shouldShowRegenerateTimings`).
3. По завершении — сбросить `approved` для сегмента, обновить статус.

**Electron** `[высокая]`
1. Добавить в `App.tsx` обработчик `handleRetranscribeCurrent()` — повторный вызов транскрипции текущего чанка через тот же путь, что и первичная транскрипция (IPC/`window.electronAPI` для локального движка либо облачный вызов Gemini/GPT), затем `onUpdateChunk(currentChunkIndex, { original: ..., approved: false })`.
2. Добавить кнопку «Try Transcription» в тулбар ревью (`:2429–2467`) или в нижнюю панель действий.
3. Удалить/переписать мёртвый `ChunkReview.tsx` либо подключить его корректно (рекомендуется удалить, чтобы не плодить путаницу).

### 4.4 Критерии приёмки
- В обеих версиях в ревью есть видимая кнопка ре-транскрибации текущего сегмента.
- Нажатие заново транскрибирует сегмент, обновляет текст и снимает отметку «approved».
- Работает и для облачного, и для локального транскрайбера.

## 5. Пункт 4 — Retry Translation и добавление языков перевода

### 5.1 Текущее состояние

**Apple Silicon — реализовано полностью.** `[высокая]`
- **Retry Translation:** кнопка в `ReviewWorkspaceView.swift:364–376` → `store.retryCurrentTranslation()` (`WorkflowStore.swift:1190`). Повторно переводит текущий сегмент на активный целевой язык выбранным провайдером (облако/MLX). Условие показа — `shouldShowRetryTranslation` (`:452–455`).
- **Добавление языка:** блок «Add» в `ReviewWorkspaceView.swift:391–412` — пикер `supportedTranslationLanguages` (12 языков, `WorkflowStore.swift:183–185`) + кнопка «Add Translation» → `store.addTranscriptTranslation()` (`:1084`). Метод переводит **все сегменты** сессии на новый язык и добавляет его в архив переводов.
- **Переключение языка:** пикер `Views/ReviewWorkspaceView.swift:378–389` (когда `archivedTranslationLanguages.count > 1`) → `store.activateTranslationLanguage(_)` (`:1074`). Модель хранит несколько переводов на сессию (`session.availableTranslationLanguages`, `WorkflowStore.swift:187–188`), реплики — `chunk.setTranslation(..., language:)`.
- Есть и покьюовый повтор: `retranslateCue(_:)` (`:939`).

**Electron — обеих функций нет.** `[высокая]`
- Целевой язык — единственная строка `session.targetLang` (`src/types.ts:70`, использование по всему `App.tsx`). Модели «несколько переводов на сессию» нет.
- Тулбар ревью (`App.tsx:2429–2467`) содержит только «Editing Model» + режим просмотра Source/Translated/Dual. Ни Retry Translation, ни пикера добавления языка, ни переключателя языков.
- Поиск по `retry/retranslate/addLanguage/availableTranslationLanguages` в `src/` — совпадений нет.

### 5.2 Целевое поведение (Electron)

1. **Retry Translation** — кнопка в ревью, повторно переводящая текущий сегмент на активный целевой язык выбранным провайдером.
2. **Мультиязычность** — возможность добавить дополнительный целевой язык к уже транскрибированной сессии (перевести все сегменты на новый язык) и переключаться между сохранёнными языками перевода.

### 5.3 Что менять (Electron)

1. **Модель данных (ключевое).** Заменить одиночный `session.targetLang: string` на архив переводов: `translations: Record<lang, {...}>` на уровне чанка и `availableTranslationLanguages: string[]` + `selectedTranslationLanguage` на уровне сессии. Портировать семантику из native `SessionModels.swift` (`chunk.setTranslation/translationText/translationCues`, `session.setActiveTranslationLanguage`). Это затронет сохранение/загрузку проектов и экспорт. `[высокая]` — самый крупный по объёму пункт.
2. **Retry Translation.** Обработчик `handleRetryTranslation()` в `App.tsx` (аналог `retryCurrentTranslation`) + кнопка в тулбаре ревью.
3. **Add language.** Пикер поддерживаемых языков + кнопка «Add Translation» (аналог `addTranscriptTranslation`, перевод всех чанков на новый язык) + переключатель активного языка (аналог `activateTranslationLanguage`).
4. **Экспорт.** Обновить экспорт документов/субтитров, чтобы можно было выгружать выбранный из нескольких языков (сейчас предполагается один `targetLang`).

### 5.4 Критерии приёмки
- В ревью Electron есть кнопка Retry Translation, повторно переводящая текущий сегмент.
- Можно добавить второй/третий целевой язык к существующей сессии и переключаться между ними.
- Переводы по языкам сохраняются в проект и корректно экспортируются.

## 7. Прочие расхождения (полный аудит)

1. **Вкладка настроек «Statistics».** Electron: 8 вкладок, включая `Statistics` (`SettingsModal.tsx:11`). Native: 7 вкладок (`Models/SettingsTab.swift` — apiKeys, models, appearance, glossary, chunking, transcription, prompts), отдельной вкладки статистики нет. Требует решения: добавлять ли статистику использования в native. `[высокая]` (факт наличия), `[средняя]` (нужно ли унифицировать).

2. **Экран визуального редактора клипов.** Native выделяет `visualEditor` как отдельный экран (`UniversalWorkflowScreen`), UI — `Views/VisualClipEditorView.swift` (236 КБ). В Electron визуальное редактирование субтитров/клипов реализовано компонентами `components/subtitle-alignment/*` и `src/render-engine/*`. Функционально близко, но стоит отдельно сверить фичи редактора (интро/аутро, лого, треки). Вне рамок 4 пунктов, но входит в «полный паритет». `[средняя]`

3. **Мёртвый код в Electron.** `src/components/ChunkReview.tsx` и `src/components/WorkspaceView.tsx` не импортируются в `App.tsx`. Кнопки в `ChunkReview.tsx` без обработчиков вводят в заблуждение (см. §4). Рекомендация: удалить при рефакторинге. `[высокая]`

4. **Набор провайдеров.** Cloud совпадает (Gemini, GPT). Локальные движки различаются осознанно (llama.cpp/whisper.cpp ↔ MLX/Core ML). В legacy-коде `App.tsx` встречаются функции перевода через Claude/OpenAI/Custom — в актуальном `provider-registry.ts` их нет; уточнить, нужен ли Claude как облачный провайдер в обеих версиях. `[средняя]`

5. **Планировщик Shorts/Reels.** Уже приведён к паритету в native (облачная ветка + fallback на MLX) в предыдущей итерации — оставляю здесь как «сделано», пункт закрыт.
